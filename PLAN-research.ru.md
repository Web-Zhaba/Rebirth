# Исследования, эпохи и восстановление построек

> Статус: реализовано R1–R4, H1–H2, T0–T1 (коммиты dab22e1…26af2ca). Не сделано: P (подсказка «первые шаги»), B (баланс).
> Заменяет для ближайшей реализации: §4, §7, §9–§10 [PLAN-tech.ru.md](PLAN-tech.ru.md) и §5, §8, §11 [PLAN-heritage.ru.md](PLAN-heritage.ru.md).
> Остальное в тех документах (мир, архив, мультиплеер, экономика камня) — без изменений и вне рамок.

## 1. Что делаем

1. **Древо технологий вместо целей.** Цепочка целей (`src/sim/goals.ts`) удаляется целиком. Всё, что сейчас открывают цели, открывают технологии. Двух механик прогресса больше нет.
2. **Эпохи.** Эпоха I «Поселение» длится до сотни жителей (~1–1,5 ч игры) и вмещает почти весь нынешний контент. Эпоха II «Деревня» открывается по технологиям и населению и приносит каменные дороги и мосты, погреб, пасеку и школу.
3. **Типизированные находки.** Раскоп находит не только безликие фундаменты, но и **постройки определённого типа** (храм, школа, рынок, мельница…). Они подсвечиваются на карте.
4. **Восстановление «как было».** Игрок восстанавливает такую постройку по реальному контуру и высоте и **выбирает её назначение**: памятник или действующее здание. За восстановление: **инсайты** к технологиям того же домена и **бонус к скорости исследований** домена. В бедных на находки местах бонус больше.
5. **Первые модели на three.js.** Восстановленные постройки рисуются процедурными 3D-моделями через уже существующий three.js-хост; это первый шаг перевода зданий на three.js.

## 2. Решения

| Вопрос | Решение |

| Цена исследования | Только время. Валюты знаний нет |
| Назначение восстановленной постройки | Выбирает игрок: «Памятник» или «В деле» (§7) |
| Инсайт к уже изученной технологии | Сгорает с сообщением |
| Мало находок (деревня) | Множитель за восстановление по плотности находок (§5) |
| Длина эпохи I | До 100 жителей, ~1–1,5 ч игры |
| Состав эпохи II | Каменная дорога, каменный мост, погреб, пасека, школа; остальное позже |
| Подсказка «первые шаги» | Можно, если дёшево; не приоритет (этап P) |
| Намёки на невскрытые постройки | Да (H1b) |
| Рендер восстановленных построек | three.js, процедурные модели (§8) |

## 3. Откуда берётся «тип постройки»

Факт из кода: слой зданий OpenMapTiles **не содержит** `building=*` — только контур и `render_height`. Тип есть только у POI (`class`/`subclass`: `place_of_worship`, `school`, `library`, `town_hall`, `hospital`, `castle`, `marketplace`…).

Решение: **POI внутри контура фундамента = тип фундамента.**

- `src/world/oldworld.ts`: уже читает POI (`cls`, `subclass`, `name`) и `render_height` здания. Из тайлов ничего нового не нужно.
- `src/map/excavation.ts`: перед `recordFinds` для каждого POI курируемого класса ищем фундамент, в чей контур попадает точка (`pointInRing`; при нескольких — наименьший по площади). Перестаём выбрасывать `height` и `subclass`.
- `FoundFoundation` получает необязательные `cls?`, `name?`, `height?`. Фундамент с `cls` из таблицы ниже — **значимая постройка**.
- Лимит: не больше 30 значимых построек на диск (приоритет: с именем → больше площадь).

### Класс → домен

| Домен | Классы OSM (POI `class`/`subclass`) |
|---|---|
| Строительство | `castle`, `fort`, `tower`, `monument`, `manor` |
| Земледелие | `farm`, `mill`/`watermill`/`windmill`, `granary` |
| Ремесло | `industrial`, `works`, `craft`, `mine` |
| Торговля | `marketplace`, `shop` (крупные), `railway`/`station`, `harbor` |

| Вера и здоровье | `place_of_worship`, `monastery`, `hospital`, `doctors`, `pharmacy`, `bath` |

Точный список сверить с реальными тайлами на этапе B (2–3 города). Таблица — статика в `src/sim/heritage.ts`; классификация — игровая абстракция, в текстах UI без исторической причинности.

## 4. Модель данных

```ts
// src/sim/tech.ts — статика, в сохранения не попадает
type DomainId = "build" | "farm" | "craft" | "trade" | "learn" | "care";
interface TechDef {
  id: string; era: 1 | 2; domain: DomainId; name: string;
  days: number;                 // базовое время, игровые дни
  requires: string[];
  unlocks: string[];            // ключи разблокировок: "sawpit", "zone:craft", "upgrade"…
  modifiers?: { fieldYield?: number; buildSpeed?: number };
  description: string;
}
interface InsightDef { id: string; domain: DomainId; tech: string; cut: number; text: string } // cut: доля времени

// src/sim/types.ts
type RestoreMode = "monument" | "working";
interface ProgressState {
  era: number;
  techs: string[];
  research: { active: { techId: string; done: number } | null; queue: string[] }; // done — накопленные дни работы, очередь ≤ 3
  insights: string[];           // полученные, ещё не применённые
  restored: Partial<Record<DomainId, number>>; // взвешенная сумма восстановлений по доменам (§5)
}
// SimState: progress заменяет goals
// FoundFoundation: + cls?, name?, height?, state?: "restoring" | "restored" | "lost"
// Building: + siteId?: string, restoreMode?: RestoreMode
```

Прогресс хранится как накопленная работа (`done`), а не `endsAt`: скорость меняется во время исследования (школа, новое восстановление), тик прибавляет `speed × dt`. Офлайн-догон получается без отдельной логики.

## 5. Механика исследований

- Одно активное + очередь до 3. Старт: эпоха узла ≤ текущей, предпосылки изучены.
- Тик (`clock.ts`, каждые 10 игровых минут): `done += speed × dt / DAY`. При `done ≥ days × (1 − cut)` — завершение, следующее из очереди.
- Скорость домена:
  `speed = 1 + 0,5 × доля грамотных взрослых + 0,05 × min(10, restored[домен])`, максимум 2.
  Грамотность уже считается: `coverage.literate` (`src/sim/coverage.ts:159`).
- **Множитель скудости.** Каждое восстановление добавляет в `restored[домен]` не 1, а `m`:
  `m = clamp(ЭТАЛОН / плотность, 1, 3)`, где плотность — значимых построек на км² вскрытой площади по всем завершённым раскопам, `ЭТАЛОН` подбирается на плотном городе (ориентир ~20/км²). Город с изобилием находок получает ×1, деревня с одной-двумя постройками — до ×3. `m` фиксируется в момент завершения восстановления, чтобы потом не пересчитывать прошлое. Пока нет ни одного завершённого раскопа, `m = 1`. Потолок домена `min(10, …)` общий, так что деревня быстрее до него доходит, но не превышает.
- Инсайт применяется к своей технологии автоматически. Если технология уже изучена — сгорает с сообщением «Идея уже известна». Не складывается.
- Отмена: прогресс теряется.
- Простой: если активного исследования нет, на кнопке «Наука» значок «простаивает».
- Завершение: разблокировки, модификаторы, хроника `tech:<id>`, тост, значок на кнопке «Наука», строка в «пока вас не было».

## 6. Эпохи и дерево

Темп (замер игрока): 100 жителей за ~1,5 ч реального времени **на скорости 4×**. Игровой день на 1× — ~4,7 мин с ускоренной ночью, на 4× — ~70 с, значит эпоха I — это **~75 игровых дней**. Исследование считается в игровом времени, поэтому скорость игры его масштабирует сама. Сумма дерева эпохи I рассчитана на ~60 дней: первые узлы по 1 дню (в первые минуты), поздние по 7, для перехода нужны не все. На этапе B pace-харнесс сверить с этим замером.

#### Каменная дорога и каменный мост

Сейчас дороги стоят только труд (`ROAD_KINDS` в `src/sim/roads.ts`: `labor` на метр, `maxGrade`, `crossesWater`). Добавляем:

| Вид | Ширина | Труд/м | Камень/м | Макс. уклон | Через воду |
|---|---:|---:|---:|---:|---|
| Тропа (есть) | 2 | 0,1 | — | 25 % | нет |
| Грунтовая (есть) | 5 | 1,0 | — | 12 % | нет |
| **Каменная** | 5 | 2,0 | 0,01 т | **20 %** | нет |
| Свайный мост (есть) | 4 | 2,0 | — | 10 % | да |
| **Каменный мост** | 5 | 4,0 | 0,04 т | 12 % | да |

- `ROAD_KINDS` получает `stone?: number` (т/м) и `unlock?: string` (ключ разблокировки). Камень списывается со склада при начале работ над ребром, как материалы зданий; не хватает — ребро ждёт («Нет камня»).
- **Пролёты ограничены у всех мостов** и растут с технологиями. Пролёт — самый длинный непрерывный участок воды вдоль ребра (по кускам профиля `land === "water"`). Базово: канатный мостик 25 м, свайный 30 м, каменный 60 м; `joinery` даёт свайному +15 м, `trusses` — свайному +15 м и каменному +40 м. Модификатор `bridgeSpan: Partial<Record<RoadKind, number>>` в `TechDef`; `roadCost` получает итоговые пролёты и отказывает «Пролёт 52 м: свайный мост держит до 45 м». Проверка только при прокладке: построенные мосты не трогаются.
- Выигрыш каменной дороги — уклон: город может подниматься на холмы, куда грунтовка не идёт. Скорость движения по видам дорог сейчас не различается и в план не входит.
- UI: два новых вида в группе «Дороги» в `buildMenu.ts`/`BuildBar.tsx`, свой стиль в `roadLayer.ts` (серый камень), профиль показывает расход камня. Инструмент «Восстановить» старые улицы не меняется (возвращает тропы/грунтовки/свайные мосты).

## 7. Восстановление постройки

- **На карте.** Значимые фундаменты рисуются в `ruinsLayer` цветом домена с подписью имени; клик (свой хит-тест по контуру, как в `buildingLayer.ts`) открывает `HeritagePanel`.
- **Панель:** имя (OSM), тип, домен, площадь/высота, цена, что даст (инсайт, «+N % к скорости: Знание», с учётом множителя скудости), статья Википедии, если в тетради есть совпадение по имени.
- **Выбор назначения** (при заказе восстановления):

| Режим | Когда доступен | Эффект здания | Бонус исследований |
|---|---|---|---|
| **Памятник** | Всегда | Без рабочих мест; +настроение и стоимость земли в радиусе 200 м | Полный: `m`, инсайт |
| **В деле** | Есть подходящий шаблон и он открыт технологией | Работает как этот шаблон (места, услуга, покрытие), на реальном контуре | Половина: `m/2`, инсайт |

  Соответствие «тип → шаблон»: `place_of_worship`/`monastery` → `chapel`; `school`/`college`/`library` → `school`; `hospital`/`doctors` → `healer`; `marketplace`/`shop` → `market`; `mill`/`granary` → `barn`; `craft`/`works` → `carpentry`. Остальные — только «Памятник».
  Выбор необратим (как в PLAN-heritage: восстановление — решение, а не переключатель). Сменить можно только сносом, а снос делает постройку утраченной.
- **Команда `restoreSite { siteId, mode }`** (worker, `src/sim/heritage.ts`):
  - проверки: постройка значимая, `state` пустой, режим допустим, контур не занят зданием или дорогой, дорога в пределах 30 м (иначе «Нужна дорога»);
  - создаёт `Building`: для «Памятника» — шаблон `restored`, для «В деле» — шаблон назначения; `footprint` = реальное кольцо, `height = clamp(render_height, 4, 25)`, `lot` = ориентированный ограничивающий прямоугольник;
  - цена от размера: труд `40 + 0,5 × площадь`, брёвна `площадь/20`, доски `площадь/40`, камень `площадь/30` (с клампами); строит обычная артель;
  - фундамент → `restoring`.
- **По завершении:** `restored[домен] += m` (или `m/2`), инсайт — следующий не полученный и не изученный в домене; хроника и тост «Восстановлено: <имя> — идея «…»».
- **Снос** восстановленной постройки: подтверждение, фундамент → `lost`, вклад в `restored` снимается, повторное восстановление невозможно. Полученные инсайты остаются.
- **Застройка поверх значимого фундамента** запрещена: «Здесь старая постройка: восстановите её или стройте рядом».

## 8. Модели на three.js

**Реализуемость: да.** В проекте уже есть общий three.js-хост на GL-контексте MapLibre (`src/map/clouds/three.ts`, в комментарии прямо заложено «later the buildings»), помощники кадра для глобуса и меркатора (`clouds/frame.ts`), ленивая загрузка three.js отдельным чанком и свой хит-тест зданий по контуру (`buildingLayer.ts:140`), так что клики от рендера не зависят.

План:

- `src/map/clouds/three.ts` → вынести в `src/map/three/` (общий хост, кадр), облака импортируют оттуда.
- `src/map/heritageModels.ts` (новый): чистые функции «контур + высота + класс → геометрия», тестируемые без GL:
  - стены — экструзия реального контура;
  - крыша по классу: двускатная по длинной оси ограничивающего прямоугольника (по умолчанию), шатёр/купол с барабаном (`place_of_worship`), башня-объём с шатром (`tower`, `castle`), плоская с парапетом (`industrial`, `station`);
  - цвета из палитры (`ui/palette.ts`), стадия «стройка» — полупрозрачный каркас по прогрессу.
- `src/map/restoredLayer.ts` (новый): custom layer с `renderingMode: "3d"` (общий буфер глубины с fill-extrusion), одна сцена, меши пересобираются только при смене списка построек. Координаты — относительно центра города (float64 модельная матрица, float32 вершины в метрах), чтобы не было дрожания.
- `buildingLayer.ts`: здания с `siteId` исключаются из fill-extrusion — их рисует three.js.
- Ночь и тени облаков: на первом шаге материал `MeshLambertMaterial` + общий источник «солнце» по времени суток; окна-огни и тени облаков на моделях — следующий шаг.

Порядок: **спайк 1–2 дня** (один куб на реальном контуре в глобусе и меркаторе, правильная глубина с соседними fill-extrusion, переход проекций) → модели → слой. Если спайк покажет, что глубина с fill-extrusion в глобусе не сходится, запасной путь — восстановленные постройки как fill-extrusion с отдельной крышей-полигоном, а three.js откладывается.

Дальнейший перевод всех зданий на three.js — отдельный план после этого: инстансинг одинаковых шаблонов, LOD по зуму, производительность на 10–20 тыс. жителей.

### Старые сохранения

- `parseProgress(v)`; если `progress` нет — миграция: изучены все технологии, чьи `unlocks` ⊆ (`goals.unlocks` ∪ `provenUnlocks`), вместе со всеми их предпосылками; эпоха по условию перехода. Ничего построенного не закрывается.
- Поле `goals` после миграции игнорируется. Версию сохранения не поднимаем (новые поля необязательные).
- `provenUnlocks` переезжает в `tech.ts`.
- Старые фундаменты без `cls` остаются безликими. Если клиент при загрузке перечитывает вскрытые диски, `recordFinds` должен **дополнять** `cls/name/height` у уже записанных id. Проверить на этапе H1; если не перечитывает — старые раскопы остаются без типов (приемлемо).

## 12. Тесты

- Граф: нет циклов, предпосылки существуют, эпоха узла ≥ эпохи предпосылок, каждый нынешний ключ разблокировки открывается ровно одной технологией.
- Исследование: старт, предпосылки/эпоха, очередь ≤ 3, отмена, завершение и запуск следующего, длинный офлайн проходит несколько технологий.
- Скорость: грамотность, вклад восстановлений, множитель скудости (1 без раскопов, 3 в пустой деревне, 1 в плотном городе, фиксация в момент завершения), потолок.
- Инсайты: одноразовость, применение к своей технологии, сгорание для изученной.
- Эпоха: условие (100 жителей + 12 технологий), однократный переход.
- Модификаторы: урожай, мастерские, стройка.
- Дороги: каменная проходит уклон 20 % там, где грунтовая отказывает; камень списывается при начале работ, без камня ребро ждёт; каменный мост через воду; виды закрыты до технологии.
- Миграция: старый сейв с целями → технологии без потери доступа; сейв без целей → `provenUnlocks`.
- Находки: POI в контуре → тип, наименьший контур при вложении, лимит 30, дополнение старых id.
- Восстановление: отказы, допустимость режима, контур/высота, цена от площади, «В деле» работает как шаблон (места, покрытие от фасада), «Памятник» без мест, бонус полный/половинный, снос → lost, запрет застройки поверх.
- Модели: геометрия из контура (замкнутость, высота, тип крыши по классу) — чистые функции без GL.
- Сохранение round-trip: `progress`, `siteId`, `restoreMode`, контур 3..N.
- `npm test`, `npm run build`, pace-харнесс.

## 13. Приёмка

- Целей в игре нет нигде; все прежние разблокировки открываются технологиями.
- Исследование идёт, ставится в очередь, продолжается офлайн; «Наука» показывает завершение и простой.
- Эпоха I длится до сотни жителей; переход срабатывает по условию.
- Завершённый раскоп в городе подсвечивает 5–30 типизированных построек; в деревне находки редки, но каждая весит до ×3.
- Восстановленная постройка стоит на реальном контуре, нарисована 3D-моделью на three.js, работает в выбранном режиме, даёт инсайт и бонус.
- Старые сохранения загружаются, ничего построенного не закрывается.

## 14. Риски

- **Мало типов в тайлах.** POI в OpenMapTiles на z14 разрежены; в деревне типизированных построек может не быть вообще — тогда и множитель не поможет. Исследования работают и без восстановлений (грамотность, школа).
- **Произвольный контур и «В деле».** Покрытие, доступ и рабочие места опираются на `lot` и фасад; для «В деле» нужен расчёт фасада по контуру. Это самый рискованный кусок H2 — покрыть тестами первым.
- **Глубина three.js с fill-extrusion в глобусе.** Снимается спайком T0; есть запасной путь.
- **Темп.** Pace-харнесс сейчас не совпадает с реальной игрой; пока он не перекалиброван (этап B), времена технологий — оценка. Удаление целей убирает пошаговое обучение; порядок дерева повторяет прежнюю цепочку, подсказка P — страховка.
- **Школа во второй эпохе.** Грамотность — часть скорости исследований; без школы всю эпоху I скорость держится около базовой. Это осознанно: восстановления в эпохе I весят больше.
